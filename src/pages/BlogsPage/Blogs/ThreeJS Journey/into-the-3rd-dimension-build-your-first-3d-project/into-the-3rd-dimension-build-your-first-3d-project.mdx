<h4 className="sub-title"><span>Step 4:</span> Define your 3D scene</h4>

The scene is the stage of your 3D world, the container that holds everything: your
objects, lights, and cameras. You place things in it, and at some point you ask
Three.js to render that scene. To create one, use the
[Scene](https://threejs.org/docs/index.html#api/en/scenes/Scene) class:

```js
// ... Previous code

/*
* Scene
*/
const scene = new THREE.Scene();
// A deep indigo background + matching fog give the scene depth and mood.
scene.background = new THREE.Color("#0f1020");
scene.fog = new THREE.Fog("#0f1020", 7, 16);
```

<h4 className="sub-title"><span>Step 5:</span> Mesh = Geometry + Material</h4>

Every visible object in Three.js is a **mesh**, and a mesh is just two things
combined:

<ul>
  <li><i className="fa-regular fa-circle-dot"></i> <b>Geometry</b> is the shape, the blueprint or skeleton of your object (cubes, spheres, torus, and many more).</li>
  <li><i className="fa-regular fa-circle-dot"></i> <b>Material</b> is how that surface looks and reacts to light. It can be a flat color, or it can wrap an image (a texture, like a JPG or PNG) around the geometry, the skin over the skeleton.</li>
</ul>

Put them together and you get the complete, renderable body: the mesh. Instead of a
plain sphere, let's make something cooler for our first object: a
[TorusKnotGeometry](https://threejs.org/docs/index.html?q=torusknot#api/en/geometries/TorusKnotGeometry),
whose twists catch the light beautifully as it spins. We'll pair it with a
[MeshStandardMaterial](https://threejs.org/docs/index.html?q=MeshStandardMaterial#api/en/materials/MeshStandardMaterial),
a physically based (PBR) material where `roughness` controls how polished the
surface looks and `metalness` how metallic it is. We'll also drop in a floor plane
so the knot has something to cast a shadow onto.

```js
// ... Previous code

/*
* Objects
*/
// TorusKnotGeometry(radius, tube, tubularSegments, radialSegments)
const knot = new THREE.Mesh(
  new THREE.TorusKnotGeometry(0.6, 0.2, 220, 32),
  new THREE.MeshStandardMaterial({
    color: "#8a5cff",
    roughness: 0.3,
    metalness: 0.35,
  })
);
knot.position.y = 0.4;
knot.castShadow = true;
scene.add(knot);

// A floor to catch the knot's shadow.
const floor = new THREE.Mesh(
  new THREE.PlaneGeometry(20, 20),
  new THREE.MeshStandardMaterial({ color: "#15161d", roughness: 0.85, metalness: 0.1 })
);
floor.rotation.x = -Math.PI / 2;
floor.position.y = -1;
floor.receiveShadow = true;
scene.add(floor);
```

<InfoNote>
We picked `MeshStandardMaterial` because it's PBR: it reacts to light realistically
and gives those soft, shiny highlights. If we'd used `MeshBasicMaterial` instead, it
would show a flat color and ignore lights entirely, handy for a quick "is it working?"
check, but not what we want now that we're about to light the scene. `castShadow`
and `receiveShadow` mark which objects throw shadows and which catch them; we still
have to switch shadows on in the renderer (Step 8) for them to appear.

One thing to know: a fully metallic surface (`metalness: 1`) mostly shows
*reflections* of its surroundings, so without an environment map it just looks dark.
We keep `metalness` moderate here so the coloured lights read richly on the surface;
adding real reflections with an environment map is a great thing to explore next.
</InfoNote>

<h4 className="sub-title"><span>Step 6:</span> Let's add lights</h4>

Quick story on why this step matters. Back in 2023 I was building my first 3D
website, [Trinity-2023](https://trinity-2023.vercel.app/), with a black background
and canvas. I imported a fighter drone model (the Trinity bot), added it to the
scene, and... nothing. Where was it? I scratched my head for hours: tweaking the
Blender export settings, deleting and re-importing the file. Then I read a post
that dropped a simple truth bomb: "Don't forget the lights." I added a light, and
boom, there it was, finally visible. Lesson learned: lights are the sunshine of
the 3D world. With a lit material like ours, no lights means your creation just
hides in the dark. They're also what give a scene its realism and depth. 🌟😅

<ImageSlider leftImage={withLightImage} rightImage={noLightImage} caption="Comparison of Scene with lights and shadows and Scene without lights and shadows." />

We'll layer a few lights so the knot reads as a real, solid object: a soft ambient
fill, a hemisphere light for a natural sky/ground gradient, one warm directional
"key" light that casts the shadow, and two coloured point lights (pink and cyan) on
opposite sides for a modern two-tone rim glow.

```js
// ... Previous code

/*
* Lights
*/
// Soft base fill so shadows aren't pitch black.
const ambientLight = new THREE.AmbientLight("#7f9bff", 0.3);
scene.add(ambientLight);

// Sky/ground tint for a natural gradient.
const hemisphereLight = new THREE.HemisphereLight("#6ea8ff", "#20143a", 0.5);
scene.add(hemisphereLight);

// Warm key light: the one that actually casts the shadow.
const keyLight = new THREE.DirectionalLight("#fff4e6", 3.2);
keyLight.position.set(4, 6, 4);
keyLight.castShadow = true;
keyLight.shadow.mapSize.set(2048, 2048);
keyLight.shadow.radius = 4;
keyLight.shadow.bias = -0.0001;
keyLight.shadow.camera.near = 1;
keyLight.shadow.camera.far = 25;
scene.add(keyLight);

// Two coloured accent lights for a modern two-tone rim glow.
const pinkLight = new THREE.PointLight("#ff3fb4", 18, 18);
pinkLight.position.set(-4, 1.5, -2);
scene.add(pinkLight);

const cyanLight = new THREE.PointLight("#22d3ee", 12, 18);
cyanLight.position.set(4, -0.5, 2);
scene.add(cyanLight);
```

<h4 className="sub-title"><span>Step 7:</span> Camera</h4>

The camera is not visible. It's more like a theoretical point of view: when we
render the scene, it's from that camera's vantage point. You can have multiple
cameras just like on a movie set and switch between them, but usually one is
enough. There are different types of cameras (the [Three.js docs](https://threejs.org/docs/index.html#api/en/cameras/PerspectiveCamera)
are a great reference for the rest); for now we just need one that handles
perspective, making close objects look bigger than far ones. We'll lift it up and
back a little and point it at the origin so we see both the knot and its shadow on
the floor.

```js
// ... Previous code

/*
* Camera
*/
const sizes = {
  width: window.innerWidth,
  height: window.innerHeight
};
// PerspectiveCamera(fov, aspectRatio, near, far)
const camera = new THREE.PerspectiveCamera(45, sizes.width / sizes.height, 0.1, 100);
camera.position.set(0, 1.2, 5);
camera.lookAt(0, 0, 0);
scene.add(camera);
```

<Insight>
`PerspectiveCamera` takes four values. Here's what each one means:

<ul>
  <li><i className="fa-solid fa-arrow-right"></i> <b>Field of View (45): </b> how much of the world the camera sees, in degrees along the vertical axis. A higher value gives a wider, more expansive view; a lower one feels more zoomed-in and less distorted.</li>
  <li><i className="fa-solid fa-arrow-right"></i> <b>Aspect Ratio (width / height): </b> the ratio of the camera's width to its height. Setting it to the window's width divided by height keeps the scene from looking stretched or squashed.</li>
  <li><i className="fa-solid fa-arrow-right"></i> <b>Near Clipping Plane (0.1): </b> the closest distance at which objects are still visible.</li>
  <li><i className="fa-solid fa-arrow-right"></i> <b>Far Clipping Plane (100): </b> the farthest distance objects are visible; anything beyond it isn't rendered.</li>
</ul>

`camera.lookAt(0, 0, 0)` simply aims the camera at the centre of the scene.
</Insight>

<h4 className="sub-title"><span>Step 8:</span> Renderer</h4>

The renderer's job is to do the render. Bet you didn't see that coming! We hand it
our scene and camera, and it draws the result into the canvas. A few extra settings
level it up: `antialias` smooths jagged edges, `setPixelRatio` keeps it crisp on
high-density screens without over-rendering, `shadowMap.enabled` is what finally
turns on the shadows we set up earlier, and `toneMapping` maps the bright highlights
to nicer, film-like tones.

```js
// ... Previous code

/*
* Renderer
*/
const renderer = new THREE.WebGLRenderer({
  canvas: canvas,
  antialias: true
});
renderer.setSize(sizes.width, sizes.height);
renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
renderer.shadowMap.enabled = true;
renderer.shadowMap.type = THREE.PCFSoftShadowMap;
renderer.toneMapping = THREE.ACESFilmicToneMapping;
renderer.toneMappingExposure = 1.1;
```

<h4 className="sub-title"><span>Step 9:</span> Let the user look around (OrbitControls)</h4>

Our scene already spins on its own, but it's much more fun if the viewer can move
the camera themselves. `OrbitControls` is a helper that turns click-drag into
orbiting, scroll into zoom, and right-drag into panning, all around a target point.
It isn't part of the core `THREE` object, which is why we imported it from the addons
back in Step 3. We attach it to the camera and the renderer's canvas, and turn on
`enableDamping` for a smooth, weighted feel (that one needs `controls.update()` in
the animation loop, which we'll add next).

```js
// ... Previous code

/*
* Controls
*/
const controls = new OrbitControls(camera, renderer.domElement);
controls.enableDamping = true;
```

<h4 className="sub-title"><span>Step 10:</span> Handle window resize</h4>

Right now the size and aspect ratio are read once, at startup. If the window
changes size the scene would stretch, so we listen for `resize` and update the
camera's aspect ratio and the renderer's size to match.

```js
// ... Previous code

/*
* Handle resize
*/
window.addEventListener("resize", () => {
  sizes.width = window.innerWidth;
  sizes.height = window.innerHeight;

  // Update the camera's aspect ratio, then tell it to recompute its projection.
  camera.aspect = sizes.width / sizes.height;
  camera.updateProjectionMatrix();

  // Resize the render and keep the pixel ratio capped.
  renderer.setSize(sizes.width, sizes.height);
  renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
});
```

<h4 className="sub-title"><span>Step 11:</span> Update the renderer on each frame</h4>

A 3D scene isn't a single snapshot; it's redrawn many times a second (typically 60
FPS) so motion looks smooth. We do that with a loop: `requestAnimationFrame` asks the
browser to call our `tick` function before every repaint. The key trick is to drive
animation by *time*, not by frame count. `THREE.Clock` gives us `elapsedTime` (seconds
since start), so the knot spins at the same real-world speed whether the device runs
at 30 FPS or 120.

```js
// ... Previous code

/*
* Animate on each frame
*/
const clock = new THREE.Clock();
const tick = () => {
  const elapsedTime = clock.getElapsedTime();

  // Tumble the knot so its twists catch the light and the shadow shifts.
  knot.rotation.x = elapsedTime * 0.3;
  knot.rotation.y = elapsedTime * 0.5;

  // Apply the damped controls every frame.
  controls.update();

  renderer.render(scene, camera);

  // Recursively call the tick function
  window.requestAnimationFrame(tick);
};
tick();
```

### Conclusion

Congratulations on taking your first steps into 3D on the web! In this blog
you've gone from an empty page to a shiny, tumbling torus knot lit and casting a
real shadow, and along the way you've met the core pieces you'll use in every
Three.js project: the scene, camera, and renderer, plus geometry, PBR materials,
lights, shadows, and OrbitControls to fly around it. That foundation is exactly
what the fancier stuff, shaders,
